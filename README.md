# dynamic-bot-bilibili

Bilibili 动态源插件，用于让 dynamic-bot 订阅 Bilibili UP 主的动态和直播状态，并支持解析 Bilibili 链接。

主项目：[dynamic-bot](https://github.com/Colter23/dynamic-bot)

## 功能

- 添加订阅时支持 UID 和用户名搜索。
- 检测 UP 主的新动态。
- 检测直播开播和下播。
- 解析动态、视频、直播间、用户空间和 b23.tv 短链接，视频链接可选择下载视频。
- 可在订阅时自动关注 UP 主。
- 遇到未登录或风控时自动暂停轮询，避免持续请求。

## 安装

构建插件：

```powershell
.\gradlew.bat fatJar --offline
```

把生成的 `*-all.jar` 放入主程序的 `plugins/` 目录，然后启动或重启 dynamic-bot，在后台启用插件。

当前源码需要配套使用包含 `dynamic-bot-core 0.0.7` 或更高兼容版本的主程序。旧主程序会提示先升级，避免运行时发生方法缺失错误。

## 登录

在后台的“平台登录”页登录 Bilibili 账号，支持二维码和 Cookie 两种方式，推荐用二维码。

扫码确认后会校验真实账号，再切换到新会话。Cookie 和扫码返回的长期令牌一起保存，已有会话不会被失败的登录覆盖。

现有每日账号维护任务会检查服务端是否要求续期，需要时完成换票并校验账号；读取接口明确报告未登录时，也会尝试恢复一次，恢复后最多重试该读取操作一次。关注、取关等写操作不会自动重放。网络失败会退避，原会话仍可用时继续使用。

只导入 Cookie 不包含浏览器本地存储中的长期令牌，因此仍可登录使用，但不能自动续期；已有扫码登录也需要重新扫码一次才能保存长期令牌。续期被拒绝或账号不一致时，需要重新登录，不保证 Cookie 永久有效。

启动和后台检查最多等待 4 秒，未完成时显示检查中，恢复任务继续运行；校验成功后会自动启动或恢复轮询。登录失效时会暂停动态轮询，已有维护任务仍会尝试恢复。

新凭据保存后才会确认旧凭据失效。确认遇到网络错误会按 5 分钟、30 分钟、6 小时退避重试；明确被拒绝或连续 4 次失败后，停止自动续期并在登录状态中提示重新扫码，当前会话可用时仍会继续使用。

会话保存失败会提示并在后续检查、轮询或停止时重试。请备份插件配置文件，其中包含 Cookie 和长期令牌，勿公开分享。

## 配置项

大多数情况保持默认即可。

- `轮询间隔`：多久检查一次动态和直播状态，默认 30 秒。
- `接口请求间隔`：连续请求 Bilibili 接口之间等待多久，默认 0.5 秒。
- `直播检测`：是否推送开播和下播。
- `绘图图片下载`：默认原图；弱网可选压缩图，由 B 站 CDN 等比缩放到宽度上限 1920 并以 WebP 质量 80 返回，减少绘图下载流量。保存后用于后续生成的动态和链接预览，不影响模板发送原图；表情、挂件、GIF 和已格式化的地址保持原样。高倍率绘图重视细节时建议使用原图。
- `关注分组名称`：自动关注时加入哪个 Bilibili 关注分组。
- `补发时间窗口`：启动时是否补发最近动态，默认 0（不补发）。
- `风控暂停时长`：检测到请求被拦截后暂停多久。

不建议把轮询间隔设置得很短，访问越频繁越容易触发风控。

## 订阅

在主程序后台添加发布者时，可以输入 Bilibili UID 或 UP 主用户名。搜索到发布者后，选择要推送到的 QQ 群或好友即可。

如果开启了主程序的“订阅时自动关注”，插件会尝试自动关注该 UP 主。

## 链接解析

支持动态、视频、直播间、用户空间和 b23.tv 短链接。

如果链接解析模板里包含视频占位符，视频链接会尝试下载并发送视频。视频大小上限为 0 时表示不限制。

## 使用建议

- 首次使用先完成登录，再添加订阅。
- 保持默认轮询间隔，除非确实需要更快检测。
- 订阅很多 UP 主时，优先提高轮询间隔来减少请求量。
- 经常出现风控提示时，增大请求间隔或暂停一段时间。

## 构建与测试

```powershell
.\gradlew.bat test
.\gradlew.bat fatJar --offline
```
